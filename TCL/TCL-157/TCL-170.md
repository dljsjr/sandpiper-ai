# Add the adoption CLI and exclusive repeat-safe configuration writer

Planning proposal for TCL-157. Start with failing writer and CLI tests after the read-only planner is ready.

Scope: a thin Commander entrypoint under Sandpiper devtools/, backed by the adoption module. Proposed invocation: bun --bun devtools/adoptTrailBoard.ts --dir <project-root> --tasks-dir <existing-directory> [--config-file <legacy-source>] [--dry-run]. The project root defaults to the current directory. The task-directory argument is explicit.

Completion criteria:
- Apply writes only a new <project-root>/.trail/config.json and any required parent directory. It never calls initialize, storage migrate, workspace creation, commit, push, or index repair.
- Recheck inputs and all destination candidates before exclusive creation. Test conflicting files, concurrent destination creation, write failures, and unchanged equivalent repeat runs. Existing data is never overwritten or deleted.
- Dry-run and refusal paths leave state unchanged. Diagnostics identify the source or destination that prevents adoption.

Keep this throwaway tool out of distributed packages. Do not select a consumer dependency, publish anything, or add a bulk live-rollout command.

## Verified implementation of in-place adoption

Completed in pzworlko / b833f516 with final alias-safety proof/fix in rrnrotpq / 81ed36be. CLI: bun --bun devtools/adoptTrailBoard.ts --dir <project-root> --tasks-dir <existing-directory> [--config-file <source>] [--dry-run]. It reports JSON. Task directory is explicit; root defaults to cwd. Apply rechecks selected source/configuration bytes and root/task directory identities, writes complete JSON to a private staging directory, rechecks immediately before publication, then uses a hard link to install without overwriting a concurrent destination. Staging and installation use the planned physical parent so changed aliases cannot redirect cleanup into concurrent data. Writer tests simulate interrupted writes and races, assert retained bytes and no partial canonical output, and preserve concurrent configuration. Matching repeats preserve bytes/timestamps/inodes. Seven actual-process CLI cases and fourteen writer cases pass. Commander 15.0.0 is an exact root dev dependency; the tool is registered as a Knip entrypoint, not distributed or installed into skills.
