# storage migrate silently ignores mode.repo, reporting success with a local-only branch

`storage migrate` reports success while **silently ignoring `mode.repo`**, leaving task files on a purely local branch with no connection to the external repository the user configured.

## Repro

```sh
git init . && git commit --allow-empty -m init
trail initialize
trail project create ACME --name A --description d --when-to-read w
trail task create -p ACME -t work
# configure EXTERNAL REPO storage
#   mode: { "branch": "trail-tasks", "repo": "/path/to/remote.git" }
trail storage migrate
```

Output claims success:

```
Preparing worktree (new branch 'trail-tasks')
Migration complete. Task files are now on the separate branch.
  Branch:  trail-tasks
```

Reality:

| Check | Result |
|---|---|
| `git -C .trail/tasks remote -v` | **empty** — no remote configured |
| remote's `git branch --list trail-tasks` | branch never created there |
| `git worktree list` | 2 — a purely local worktree |

The user configured external-repo storage, was told migration completed, and has a local branch that will never reach their remote.

## Cause

`migrateInlineToSeparateBranch` (`src/core/migrate.ts`) always calls `initSeparateBranch` and never `initExternalRepo`. Its own guard — `!vc.enabled || (vc.mode.branch === '@' && !vc.mode.repo)` — lets an external-repo config through without throwing, but the implementation below it only ever handles the separate-branch case. `mode.repo` is read by the guard and then ignored.

## Provenance and pattern

Found by sandpiper-dev while scoping TCL-152's reopen: they declined to point external-repo users at `storage migrate` precisely because they traced this and could not truthfully claim the command would clone the remote. The scoping decision was correct and this is the finding behind it.

**This is the third instance of one pattern in a single session**, all with the same signature — confident success message, wrong underlying state, no error:

- **TCL-152** — `storage init` no-ops on an empty dir, reports separate-branch storage initialized, creates no worktree.
- **TCL-151** — mutation with a malformed config writes the task, prints success, then crashes; auto-commit silently skipped.
- **This** — `storage migrate` ignores `mode.repo`, reports migration complete, produces a local-only branch.

Worth treating as a class rather than three unrelated bugs. Every one is a command reporting its *intent* rather than its *result*, and every one was invisible to a test suite that asserted on exit codes and printed output instead of resulting VCS state. Relevant to TCL-138's audit, and specifically to the rank-6 "separate-worktree storage furniture" candidate.

## Fix directions

1. **Route external-repo configs correctly** — `migrateInlineToSeparateBranch` dispatches to `initExternalRepo` when `mode.repo` is present, preserving the existing task files through the clone.
2. **Or refuse explicitly** — if migrating into an external repo is not supported, the guard should say so and exit non-zero rather than quietly doing the local thing.

(1) is the honest fix. (2) is acceptable as an interim if the clone-preserving-existing-files path needs real design, but the current silent third behavior is not.

Whichever lands, the regression test must assert on **resulting VCS state** — remote configured in the workspace, branch present on the remote — not on exit code or stdout. Exit 0 with a success banner is exactly what this bug produces.

Not blocking the standalone extraction. Found during TCL-146 acceptance, 2026-08-12.

## Implemented 2026-10-06

Landed the explicitly permitted safe interim direction: external-repo migrations now refuse before any backup, file deletion, workspace initialization, or VCS command. They no longer claim local separate-branch migration satisfies mode.repo. Full external clone/merge migration is not implemented.

Commit rrslompr. Regression went red then green and asserts original task bytes, absent gitignore changes, and no VCS calls. Real CLI reproduction on a temporary git repository with a local bare remote returned exit 1, left the task checksum and worktree registration unchanged, and created no remote branch. Full suite: 512 tests; typecheck clean. NEEDS REVIEW.
