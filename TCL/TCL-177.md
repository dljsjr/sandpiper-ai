# Project metadata writer fails to escape quotes and backslashes in YAML strings

Confirmed against the built standalone CLI during TCL-174. In a fresh temporary store, project create APP --name 'The "quoted" project' --description 'Path C:\temp' --when-to-read 'During maintenance' exits 0. PROJECT.md contains name: "The "quoted" project" and an unescaped backslash in description. parseProjectMetadata reads the name as 'The ' and turns backslash-t into a tab. Root: src/core/project-metadata.ts:30-35 and :113-124 manually quote unescaped input. Reuse the existing scalar encoder, keep input literal in replacements, and test create/update round trips for quotes, backslashes, Unicode, and multiline input policy. Do not rewrite whole YAML files or change read-time fallback behavior as part of the fix.
