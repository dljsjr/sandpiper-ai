# Standalone Trail: extraction and configuration cutover

Make a standalone `trail` package feasible in ~/git/trail, in the smallest form that works. Doug 2026-08-12: there is an immediate need for standalone Trail; the eventual Rust port is long-tail and must NOT influence decisions here.

Repo is seeded and green: ~/git/trail, jj colocated, baseline commit `pmzmvzly`, tsc clean, 456 tests across 30 files passing including real git/jj integration. That commit is the rollback point.

Tickets live here in sandpiper-ai on purpose. Trail's own board would sit at `.sandpiper/tasks` — the exact path this work renames — so tracking the work in the tool being modified would break the board mid-cutover.

IN SCOPE: the four subtasks below, in order. Each lands as its own commit with its own green gate.

OUT OF SCOPE, deliberately deferred. All are purely additive later and none block standalone:

- `.trail.json` and `trail.json` as extra config candidates. Ship `.trail/config.json` alone; precedence only matters once someone shadows a committed config, and nobody does yet.
- Folding `storage init` into `initialize`. UX fix, not extraction.
- Doc migration out of sandpiper-ai.
- TCL ticket migration between repos — Trail has no cross-repo move, see TCL-138 notes.
- The migration tool for Doug's twelve existing boards. It lives in sandpiper-ai, not Trail, so Trail never learns the old formats. Separate ticket once this lands.
- Audit cleanup ranks 1-6 from TCL-138.

Coordination: Roux coordinates and arbitrates, sandpiper-dev implements, sandpiper-rev reviews adversarially. One writer at a time in ~/git/trail.

The bullets above were written from memory rather than from `.sandpiper/docs/specs/trail-extraction-design.md`, and three of them recast decisions Doug **ruled settled** in the design session as optional future additions:

|---|---|
| "`.trail.json` and `trail.json` as extra config candidates… precedence only matters once someone shadows a committed config, and nobody does yet" | **[settled]** Three candidates, first match wins. Multiple present is deliberate and legal — shadowing is the *purpose*, not a hypothetical |

| *(absent entirely)* | **[settled]** "Default tasks dir is `./.trail/tasks`. Overriding it is a key in the config file" — load-bearing for the migration tool |

Tickets filed off the bad paraphrase have been rewritten against the record: **TCL-161** (candidates, LOW → HIGH), **TCL-162** (`storage init` removal), **TCL-163** (tasks-dir key), **TCL-157** (migration tool — it had been scoped to *move* task trees, the exact opposite of the settled "tasks are not moved").

**The design record is authoritative. Where it and this ticket disagree, it wins.** It is currently uncommitted in Doug's working copy, which does not make it draft.
