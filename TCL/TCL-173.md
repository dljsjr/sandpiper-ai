# Description read/update mistakes YAML comments for task headings and can delete frontmatter

Discovered while searching for the same whole-document heading assumption as TCL-167. This is a separate description-path defect; TCL-167's title-only fix does not change description handling.

Location: src/core/description.ts, extractDescription() and replaceDescription(). Both select the first /^# .+$/m match across the whole document, including YAML comments. Callers include task show and task update --desc.

Reproduction through the actual standalone built CLI:
1. Initialize a temporary no-VCS board and create APP-1 with a title and description.
2. Insert # Keep this comment immediately after the opening frontmatter delimiter.
3. Run task show APP-1 --format json. The returned description contains frontmatter fields rather than only the Markdown description.
4. Run task update APP-1 --desc "Replacement description.".

Expected: leave frontmatter/comment/title/body heading intact and replace only the description. Task show returns only the intended description.

Actual: task update exits 0 but removes the frontmatter title/status and other fields; the selected comment is treated as the body heading. This is data loss, not merely a display mismatch.

Verified after the TCL-167 fix with /tmp/trail-description-comment-repro.mjs. Scratch /var/folders/zj/49vt4cds6l15fs_1frdvz89r0000gn/T/trail-description-comment-W3AyUx. Output: updateExit=0, readLeakedFrontmatter=true, updateRemovedFrontmatter=true. All mutations were confined to the scratch board.

Filed separately per bug-tracking convention. NOT STARTED; no source fix or scope expansion. Preserve existing description/activity-log behavior outside the frontmatter-boundary correction. Sandpiper's unrelated refactor and all live boards remain untouched.

## Fix and verification

Standalone Trail commit ksyrqsys / c628da3f fixes both extractDescription and replaceDescription. A shared private lookup uses the existing frontmatter extractor to restrict heading search to the body, then retains the absolute match offset. It does not search the whole document again by heading text, so an identical YAML comment cannot redirect the boundary. No change to the title fix, activity-log layout, or other mutation behavior.

Test-first: the read regression failed because metadata leaked into the description. After the reader fix passed, replacement/clearing regressions failed because they deleted frontmatter. Both now pass. Five new cases cover identical comment/heading text, absent body heading, replacing and clearing a description with an existing activity log, and a public updateTaskFields round trip preserving all metadata except the intended timestamp. Baseline 589 tests / 37 files; final 594 / 37, TypeScript and build pass. Relevant description/title tests pass together (110 tests).

Actual built CLI runner /tmp/trail-tcl173-cli.mjs passes description reading, replacement, clearing, and a combined title/description update. It verifies unchanged metadata/comments and retained activity log. Retained scratch /var/folders/zj/49vt4cds6l15fs_1frdvz89r0000gn/T/trail-tcl173-fixed-Hzs9G3.
