# jj auto_commit leaves task branch bookmark behind

# Bug: jj auto_commit does not advance configured task branch bookmark

## Observed behavior

In `/Users/dstephen/git/reinforced-guidance`, task storage was configured for current-repo branch/workspace mode:

```json
{
  "version_control": {
    "enabled": true,
    "mode": { "branch": "sandpiper-tasks" },
    "auto_commit": true,
    "auto_push": false
  }
}
```

After migration, running:

```bash
sandpiper-tasks task complete RG-179
```

auto-committed the task change in `.sandpiper/tasks`, but the `sandpiper-tasks` bookmark stayed on the previous import commit instead of advancing to the new auto-commit.

Observed task workspace shape:

```text
@  zwrrzytx ... tasks@ ... (empty) (no description set)
○  kynznmmk ... Completed 1 task → NEEDS REVIEW.
○  znpmvkwy ... sandpiper-tasks | Import reinforced-guidance tasks
```

## Impact

`storage push` would push stale task state unless the bookmark is moved manually, because the configured task branch bookmark remains behind future auto-commits.

## Likely fix

After jj auto-commit, ensure the configured branch bookmark tracks the newest committed task change. For example, after `jj commit -m ...`, move the bookmark to the committed parent of the empty working copy:

```bash
jj bookmark set "$branchName" -r @-
```

Use the storage abstraction's configured branch name and preserve the existing git backend semantics.
