# Purge sandpiper naming from Trail test fixtures (106 refs, 7 files)

Trail's production source is clean of `sandpiper` — verified by search across `src/**/*.ts` excluding tests, and in the built binary. Its **test fixtures are not**: 106 references across 7 files.

| File | refs |
|---|---|
| `src/core/storage-backend.test.ts` | 54 |
| `src/core/storage-backend.integration.test.ts` | 26 |
| `src/commands/storage-cmd.test.ts` | 10 |
| `src/core/fs.test.ts` | 7 |
| `src/core/auto-commit.integration.test.ts` | 5 |
| `src/core/storage-config.test.ts` | 3 |
| `src/core/auto-commit.test.ts` | 1 |

Mostly `sandpiper-tasks` branch names and `.sandpiper/tasks` fixture paths, e.g. `writeStorageConfig(rootDir, { mode: { branch: 'sandpiper-tasks' } })` and `join(rootDir, '.sandpiper', 'tasks')`.

**Confirmed cosmetic, not a hole in TCL-148.** `initSeparateBranch`/`initExternalRepo` take the workspace path as a caller-supplied parameter, so the tests are passing arbitrary strings that happen to be spelled `.sandpiper`. Production never derives that path. The suite would pass identically with any other name.

Worth doing anyway: this is a repo whose stated purpose was zero `sandpiper`, and a reader grepping for it finds 106 hits and has to re-derive that they are inert. Straight rename to `.trail`/`trail-tasks` with the suite as the gate.

Found during TCL-146 acceptance, 2026-08-12.

## Implementation and verification — 2026-10-06

This includes real Git/JJ worktree/clone fixtures, command expectations, upstream checks, gitignore examples, and the ignored-settings-file case.
