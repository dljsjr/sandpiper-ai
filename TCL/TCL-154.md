# bun test runs the wrong runner and reports a convincing false red

Trail's suite is a vitest suite (`"test": "vitest run"`, `vitest.config.ts`). Bun's own runner also collects `src/**/*.test.ts`, so `bun test` runs — and produces a detailed, entirely fake failure report.

Observed 2026-08-12 at `vqymwsny` (tip):

- `bun run test` → 32 files, **487 passed**, exit 0.
- `bun test` → 487 collected, **21 failed**, exit 1.

The false failures are convincing. They name real test cases with real assertions (`expect(result.exitCode).toBe(0)` / `Received: 1`), they cluster plausibly around storage init/migrate/sync, and they include tests marked "real git integration" — exactly the shape you would expect from a broken VCS seam. Nothing in the output says "wrong runner."

Root cause: the tests import from `vitest` (`vi.spyOn`, `vi.mock`) and rely on vitest's module-instance semantics for the `setVcsRunner`/`resetVcsRunner` seam in `storage-backend.ts`. Under Bun's runner the spy/module semantics differ, so the fake runner never intercepts and the command layer shells out to real git in a temp dir with no repo.

Why this matters more than a footnote: `bun test` is the natural muscle memory in a Bun project, and this failure mode costs real time — it burned an agent session into filing a false "HEAD is red" alarm against a green tree, and the same mistake reproduces in `sandpiper-ai/packages/trail`. A test command that lies is worse than one that refuses.

Proposed fix (small, does not touch the suite): add `bunfig.toml` with a `[test]` preload that fails immediately with a message naming `bun run test`. That converts a plausible false red into an unmissable one. A CONTRIBUTING/AGENTS note is a weaker second choice — it only helps whoever reads it first.

Related class: this is the same shape as TCL-151/152/153 — a command reporting something other than its actual result — except here the misreport is the tooling's, not Trail's own.

## Implemented 2026-10-06

Doug approved the guard. Added a test-only preload in bunfig.toml and scripts/reject-bun-test.js. The guard exits 1 with: Trail uses Vitest. Run "bun run test" instead of "bun test". Existing Vitest configuration and tests are unchanged.

Regression test src/test-runner.integration.test.ts failed before the fix and passed afterward. It spawns Bun with a temporary canary test and verifies that its module never loads. The full Vitest suite passes: 488 tests across 33 files. bun run check passes. Plain bun test exits immediately with the diagnostic. bun src/index.ts --help still exits 0.

## Implementation and verification — 2026-10-06

Committed `yuxutmlm` / `15f98b03`: a Bun preload guard rejects `bun test` before test modules load, directing the caller to `bun run test` (Vitest). An integration regression verifies the failure message/exit code and that ordinary Bun CLI execution remains unaffected. This configuration guard was explicitly approved by Doug. Final cumulative gate: 524 tests / 33 files pass and `bun run check` passes. Left NEEDS REVIEW.
