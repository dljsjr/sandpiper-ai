# Close check 1a gap: enforce via enforceUpdateFieldGuards, not just completeTask

Huginn found this while doing the requested final review round: checkChildrenCompleteBeforeFinalize (check 1a) was only ever called from completeTask in mutate.ts. task update PARENT --status COMPLETE --resolution DONE reaches updateTaskFields directly (confirmed already-passing test at mutate.test.ts proving this call shape is legal) and finalized a parent with wide-open subtasks with zero validation. The new --interactive routing had the identical gap, since it also only calls enforceUpdateFieldGuards.

Fix: moved the check 1a call into enforceUpdateFieldGuards itself, gated on fields.status === 'COMPLETE' (not gated by the WONTFIX exemption -- Doug's decision that check 1a stays unexempted holds). Removed the now-redundant direct call from completeTask, which reaches the same check through its existing call to updateTaskFields at the end. Updated the 'sequential gates' comment on completeTask to point at the new call site. This closes the gap uniformly for task complete, task update --status COMPLETE, and the interactive path all at once, per Huginn's suggested fix.

Also folded in two smaller polish items Muninn flagged in the same review round:
- Extracted assertCompleteRequiresResolution (consistency-guards.ts) as the single shared definition of 'COMPLETE requires a resolution', replacing two independent copies (updateTaskFields's inline check, and the --interactive branch's duplicate) that happened to currently agree but had no shared source.
- Fixed the plan doc's 'immediately' wording describing check 1b's trigger timing -- it fires the next time someone explicitly sets status on an affected child, not proactively, consistent with every other guard here being write-time-only, not a corpus-wide sweep. Added a one-line cross-reference comment on checkChildrenCompleteBeforeFinalize pointing to the plan doc's WONTFIX-exemption reasoning, since a spec doc isn't what's open when someone's editing that function months from now.

Verified: new regression test (mutate.test.ts) proving updateTaskFields directly -- not just completeTask -- now blocks finalizing a parent with open subtasks. End-to-end CLI smoke test confirms the exact gap Huginn described is closed. 431/431 tests pass, tsc/biome clean.
