# Unchecked CLI enums allow invalid priority, kind, and completion resolution

Confirmed against the built standalone CLI during TCL-174. Create APP-1 normally. task update APP-1 --priority URGENT exits 0 and writes URGENT, but canonical reads show MEDIUM. task complete APP-1 --final --resolution TYPO exits 0 from NOT STARTED and writes status COMPLETE/resolution TYPO, but canonical reads omit resolution. Root: buildFieldsFromOptions returns Record<string, unknown>; create/move/complete also uppercase strings and assert domain types without parsing. Parse supported enum values at the CLI boundary, return UpdateFields rather than a generic record, and test rejected inputs leave bytes/index/history unchanged. Preserve the documented permissive reader for existing files.
