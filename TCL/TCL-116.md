# Understand and develop a workaround for the branch + workspace storage + auto-commit configuration leading to stale JJ workspaces

Investigation update: backed out the attempted source-dirty auto-commit guard and task-workspace update-stale preflight. The evidence now points away from a sandpiper-tasks-specific main-workspace interaction. Normal task mutations only invoke jj in the dedicated task workspace during auto-commit; storage init/migrate are the commands that intentionally touch the root workspace. The more plausible root cause matches upstream jj issue #7538: watchman/fsmonitor plus concurrent edits/snapshots across workspaces can race and leave a workspace stale/divergent. Sandpiper enables watchman, and task storage creates an additional workspace being edited/committed while agents edit the default workspace, so it likely increases exposure to that upstream race even though the workspaces track different trees.
