# Add mutation-time consistency checks (parent/child, blocker resolution, dangling refs, cycles)

Implements .sandpiper/docs/specs/trail-consistency-checks-plan.md (reviewed and converged by Huginn and Muninn before implementation, then code-reviewed by both after implementation -- two real rounds, not rubber stamps).

Four hard-error-by-default checks, demotable to warning via --force, enforced inline at mutation call sites:
1. Parent/child status consistency (bidirectional).
2. Blocker-resolution consistency -- fails closed on a dangling blocker key (Muninn's finding: the original silent-skip created an unguarded gap when a stored, not freshly-set, blockedBy reference goes dangling, since checkReferencesExist never runs in that call shape).
3. Dangling relationship references.
4. Cycle detection.

NEEDS-REVIEW-before-DONE stays untouched, unconditional, no flag.

Post-implementation code review (Huginn + Muninn, both against the actual diff) found and fixed:
- checkBlockersResolved's silent skip on dangling keys -> fails closed now, plus a new regression test for the exact gap (mutate.test.ts, 'blocks finalizing when a stored (not freshly-set) blocker reference has gone dangling').
- updateTaskFields CC 20 -> 4 and createTask CC 14 -> 10, via new enforceUpdateFieldGuards/enforceCreateTaskGuards orchestrators in consistency-guards.ts (verified with lizard before/after, not just asserted).
- Shared isActiveUnderCompleteParent predicate extracted; move.ts no longer reimplements the same boolean inline.
- console.warn -> console.error in enforceGuard (Trail has no console.warn precedent anywhere).
- Fixed a wrong docstring and added a missing explanatory comment (why createTask never calls checkNoCycle).
- Documented that completeTask's two guards are sequential, not simultaneous: only the first violation surfaces per call.

Also surfaced and caught, as a side effect of double-checking a reviewer's numbers rather than trusting them: a real lizard bug where brace-depth tracking desyncs near template literals / multi-line inline object-type annotations, silently swallowing sibling functions into a preceding function's reported CC. Not a Trail issue, but worth remembering for future lizard-based audits in this repo.

Verified final state: check:tsc clean, check:biome-check clean, full packages/trail/ suite passes (421 tests), end-to-end CLI smoke test still holds.

Known gaps, unchanged from before, still deliberately out of scope: the 4 orphaned query.ts relation-getters (not reused, not deleted), and task update --interactive bypassing all 4 guards (same as it already bypasses other updateTaskFields validation).
