# Roll toon 4.1.1 to every board consumer before any 4.x Trail writes a board

Trail now writes `index.toon` with `@toon-format/toon` 4.1.1 (TCL-155, commit `wprskpsx`). **Toon 4.x output is not readable by 2.3.x.** Upgrading any board's index is a one-way door, and every consumer must be on 4.x before anything writes a real board.

## The asymmetry, measured

| Reader | 2.3.x-written index | 4.x-written index |
|---|---|---|
| 2.3.0 | OK | **FAIL** — `Invalid array length: "10:"` |
| 2.3.1 | OK | **FAIL** — same |
| 4.1.1 | OK | OK |

Verified against sandpiper-ai's live 7871-line index. v4 encodes objects-of-uniform-objects as keyed tabular rows; on that index only the `counters` block qualifies (task entries are ragged and stay nested), so the diff is 46 lines and the file shrinks 328 bytes. Small change, total incompatibility.

The failure mode is indistinguishable from the bug TCL-155 fixes: a board that reads fine one moment and throws a parse error on every command the next, with `index update` unable to repair it.

## Consumers still pinned at 2.3.0

1. `packages/trail` — the vendored copy.
2. `packages/capability-autotoon`.
3. **`packages/resources/skills/sandpiper/tasks/scripts/trail`** — the bundled 243KB node script (built 2026-08-10) with toon compiled in. This is the binary that runs every board operation on this machine today. A stale bundle here means a rebuilt package elsewhere does not protect anything.

Item 3 is the one that bites, because it is a build artifact rather than a dependency declaration — bumping `package.json` in the other two does not touch it.

## Order (readers before writers)

1. Vendor Trail at or after `wprskpsx` into `packages/trail`.
2. Bump `@toon-format/toon` to 4.1.1 in `packages/capability-autotoon`.
3. **Rebuild the tasks skill script bundle** and verify the artifact: run it against a scratch board whose index has been re-encoded by 4.1.1 and confirm it reads rather than throwing `Invalid array length`. Check the artifact, not the manifest.
4. Only then let any 4.x Trail write a real board.

Until step 3 lands, do not point standalone Trail at any board under `~/git`. Twelve boards on this machine are currently served by the 2.3.0 bundle.

## Relationship to the migration tool

The board migration tool (deferred out of TCL-146, lives in sandpiper-ai) rewrites indexes anyway, so the format change should ride along with it rather than being a separate migration event. That was the reasoning for taking 4.1.1 over the 2.3.1 patch. It does not remove this ordering constraint — it just means the rewrite has a natural home.
