# pushTaskBranch bare git push fails on first auto_push without upstream

Confirmed via fully-isolated scratch repro (GIT_CONFIG_GLOBAL/SYSTEM neutralized, mirrors real flow: worktree --orphan, remote added, commit, bare push): packages/trail/src/core/storage-backend.ts:159 pushTaskBranch() runs a bare `git push` with no --set-upstream and no explicit remote/branch. Separate-branch mode creates the task branch via initGitWorktree() `git worktree add --orphan -b <branch>` (storage-backend.ts:74), which never establishes upstream tracking - so the FIRST auto_push after storage init fails with "fatal: The current branch <branch> has no upstream branch" unless the user happens to have push.autoSetupRemote set globally (which masked this on the primary dev machine) or has manually run `git push -u` once. External-repo mode likely shares the gap when checkoutOrCreateBranchGit() (storage-backend.ts:130) falls back to `git checkout -b <branch>` for a branch absent on the remote.

Fix direction: push with `--set-upstream origin <branch>` (or equivalent) at least when no upstream is configured; cover both separate-branch and external-repo first-push paths. Discovered 2026-08-06 while isolating trail tests from real user git config - the auto-commit test "pushes to remote when auto_push is true" only ever passed via the developer machine's push.autoSetupRemote. The test-side companion (upstream established in setup, mirroring post-first-manual-push steady state) rides in the test-isolation change; this ticket owns the product fix.
