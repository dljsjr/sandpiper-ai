# Missing frontmatter field lets task update overwrite matching description text

Confirmed against the built standalone CLI during TCL-174. Create APP-1 with description 'priority: body text'. Remove only priority from frontmatter using a text editor. Run task update APP-1 --priority HIGH. Exit is 0. Frontmatter still lacks priority, but description becomes 'priority: HIGH' and the activity log records a successful priority change. Root: src/core/mutate.ts:289-291 ignores the field range returned by assertRoundTrippableFieldForm and applies a whole-document regex even when the field is absent. Keep replacements within frontmatter. Define missing-field behavior explicitly (insert or refuse) and test body/history preservation. This is distinct from the fixed title/description YAML-comment bugs TCL-167/TCL-173.
