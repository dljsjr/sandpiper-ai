# Audit Trail code health with anti-slop lens

Trail-only deep health audit using the anti-slop/code-quality lens.

Scope:
- Source TypeScript under packages/trail/src/**/*.ts plus package-local config/tests that shape Trail behavior.
- Generated packages/trail/dist/**/*.d.ts is out of scope as source code; inspect only if packaging/public surface questions require it.
- Keep Shell Relay, Chorus/Zellij, standalone bootstrap, and extension inventory outside the cone unless they directly affect Trail.

Audit rules:
- Reading and holistic judgment are primary. Tools are token-efficient guidance and supplemental evidence, not gospel gates.
- A proper audit eventually gives every in-scope Trail TypeScript file eyes, staged over multiple passes if needed. Otherwise call the work sampling, not an audit.
- Dora is code cartography first; metrics are lagniappe.
- Human findings lead; tool signals sit underneath as evidence.
- Each cleanup candidate must name earned vs accidental complexity, the cheapest dumb form, risk, and a verification gate.
- No code cuts before the audit/concept/coverage ledger exists.

Initial artifacts:
1. Boundary + concept map.
2. Coverage ledger for in-scope TS files.
3. Findings ledger: finding, evidence, earned/accidental complexity, cheapest dumb form, risk, gate, candidate slice.
4. Prioritized cleanup recommendations.
