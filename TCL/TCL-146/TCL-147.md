# Slice 1: extract path/config location module (behavior-preserving)

Collapse the ~16 hardcoded path literals into one module that names the concept nobody named: where the task tree and its config live.

Today that concept is open-coded across `commands/helpers.ts`, `commands/storage-cmd.ts` (5 sites), `core/migrate.ts` (4), `core/storage-config.ts` (2), `core/editor.ts`, and `src/index.ts`, plus a matching set of doc comments. Changing the convention currently means a 16-site sweep with no compiler help.

THIS SLICE CHANGES NO BEHAVIOR. Paths still resolve to `.sandpiper/tasks`, `.sandpiper-tasks.json`, and `.sandpiper/settings.json`. The literals move; they do not change value.

Verification gate, and it is a hard one: **all 456 tests pass with ZERO test-file edits.** If a test needed changing, the refactor changed behavior and is wrong. `tsc --noEmit` clean.

Notes:
- `--dir` already means project root (the container), not the tasks dir. Do not change that.
- Temp-dir prefixes (`sandpiper-migrate-`, `sandpiper-edit-`) are cosmetic; carry them into the module but do not rename yet — renaming is slice 2's business.
- Keep the module dumb. Constants and one or two resolvers. No config-loading logic; that is slice 3.
