# Slice 4: initialize command

New top-level `initialize` command. It is the only way to produce a config, so it has to produce a complete one.

- Emits `./.trail/config.json` with **every default explicitly populated**, including `version`. Nothing implicit — the file it writes must be a file slice 3's strict parser accepts.
- **Never overwrites.** If a config already exists at any candidate path, fail loudly and name the file found. An existing config means either `initialize` already ran or the user deliberately bootstrapped their own; neither is Trail's to clobber.

Do NOT fold `storage init` into this yet. That is a deferred UX cleanup and is out of scope for the cutover.

Verification: `tsc --noEmit` clean, suite green, tests covering: fresh directory produces a config the strict parser round-trips; second invocation fails loudly without touching the existing file; emitted config contains every key the parser requires (this test is the real one — it pins `initialize` and the parser to each other, so they cannot drift apart).
