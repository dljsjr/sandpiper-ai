# Field updates interpret literal dollar sequences as replacement syntax

Confirmed against the built standalone CLI during TCL-174. In a fresh temporary no-VCS store, create APP-1 with title ORIGINAL, then run task update APP-1 --title '$&'. Exit is 0, but stored title becomes 'title: ORIGINAL' and heading becomes '# # ORIGINAL', while the activity log claims the new title is '$&'. With a quoted original title, the update instead fails during subsequent YAML checks. Root: src/core/mutate.ts:265-291 interpolates input into String.replace replacement strings. Project metadata updates have the same replacement-string shape. Use literal replacement callbacks or source-range splices. Add CLI tests for $&, $`, $', and $$ before fixing. Do not combine the bug fix with the broader task-document refactor.
