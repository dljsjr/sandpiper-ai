# Consider .trail.json and trail.json as additional config candidates

Trail resolves exactly one config location today: `.trail/config.json` (`CONFIG_FILE_SEGMENTS` in `storage-paths.ts`). The design record settles three.

## Settled design

`.sandpiper/docs/specs/trail-extraction-design.md`, "Config resolution" — marked **[settled]**, ruled in the 2026-08-12 design session. Candidates, highest precedence first, **first match wins**:

1. `./.trail.json`
2. `./trail.json`
3. `./.trail/config.json`

No merging, no walking up the directory tree, no environment variable override.

Multiple candidates present is **deliberate and legal, not an error**. It exists so a user can clone a repo carrying a version-controlled Trail config and shadow it with a local uncommitted one — working on a fork while tracking their own board. Prior art is mise's `mise.toml`/`mise.local.toml` family, cited as an existence proof that layered filenames are fine and explicitly **not** as a template: mise merges hierarchically because its surface demands it, Trail's does not.

Also settled there: the `tasks` key inside `.sandpiper/settings.json` is dropped entirely. Trail does not know that format exists.

## `initialize` is currently incorrect against this

The settled `initialize` rule is: "**Never overwrites.** If a config already exists at **any candidate path**, `initialize` is a no-op consumer and fails loudly." Today `initialize-cmd.ts` checks `configFilePath(rootDir)` — the single canonical path — so once the other two candidates exist, `initialize` will happily write `.trail/config.json` over a project already configured by `./.trail.json`. Fixing the candidate list and fixing that check are the same change and should land together.

## Correction to this ticket's original framing

Filed 2026-08-12 as "*Consider* `.trail.json` and `trail.json` as additional config candidates" at LOW priority, with reasoning arguing precedence might never be needed and independently re-deriving "first-found is the cheaper and more honest answer." That was a settled design decision demoted to speculation and then reinvented. The source of the error was TCL-146's deferred list, which paraphrases the settled decision as an optional extra; the design record wins over the ticket.
