# task update fails on relationship fields written after updated_at

`task update --depends-on/--blocked-by/--related` fails with `Cannot update frontmatter field "updated_at" because its YAML form is non-round-trippable by Trail's surgical writer.` when the relationship array is the last frontmatter field, after `updated_at`. `task create` with relationships writes them in that order, so every task created with `--depends-on` hits this on its first relationship change.

Cause: `replaceArrayField()` in `src/core/mutate.ts` removes the existing array with `^<field>:.*(?:\n  - .+)*`, which leaves an empty line between `updated_at` and the closing `---`. The comment there assumes `updated_at` is always the last field. `touchUpdatedAt()` then runs `assertRoundTrippableFieldForm()`, and `findFrontmatterFieldForm()` counts that empty line as a continuation line of `updated_at`, so the check throws.

Repro (`applyFieldUpdates(content, { dependsOn: ['A-2'] })`):
- `depends_on` after `updated_at`: throws.
- `depends_on` before `updated_at`: ok.

Live hit: 2026-10-06, `task update AGENT-295 --depends-on AGENT-293` and the same on AGENT-296. Worked around by editing the files directly. `~/git/trail` has the same `replaceArrayField()`.
