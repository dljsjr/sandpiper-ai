# Frontmatter edit guard falsely refuses plain scalars containing ampersand or asterisk

`assertRoundTrippableFieldForm` / `isRoundTrippableFieldForm` in `mutate.ts` refuse an edit when a field value contains ` &word` or ` *word`, because the regex `/\s[&*][A-Za-z0-9_-]+/` cannot distinguish a real YAML anchor/alias (a node-position construct) from those characters appearing mid plain-scalar.

Repro: set a task title to `Add &ref support`, then edit that task. The guard fires and the edit is refused. Fail-loud-safe \u2014 nothing is corrupted \u2014 but it is a plausible title and the refusal is wrong.

Root cause is structural, not a bad regex: the guard detects YAML forms with regex heuristics on raw text while the codebase now owns a real `yaml` parser (Option-A swap). That is a parallel representation of YAML-form knowledge.

Fix: replace the regex form detection with parser node-type inspection \u2014 `isScalar` plus block-scalar type, `isMap`, `node.anchor`. Precise instead of heuristic; removes the false positive and the parallel representation together.

Found during the TCL-138 audit, in a review of the parser-swap commit `679c5e55`. It lived only as a fact in Roux's YAAMS memory until 2026-08-12; filed so it survives the Trail repo extraction.
