# jj automatic commits do not advance the task bookmark before pushing

Confirmed during TCL-174 with real jj and a local-only bare Git remote. Initialize temporary jj code repo and add local origin. trail initialize --branch tasks --auto-commit --auto-push. Create APP-1 then APP-2. Both CLI calls exit 0. Bookmark tasks remains on the first creation commit. The second creation commit is its descendant, and the remote tasks tree contains APP-1.md but not APP-2.md. Root: commitTaskChanges invokes jj commit, which does not move bookmarks, then pushTaskBranch pushes the unchanged bookmark. Advance the configured bookmark to the committed revision before automatic push, preserving unrelated bookmarks. Add a real-jj integration test with two consecutive mutations and inspect the remote tree, not just command invocations. No network publication or live-repository changes are required. Probe logs: /tmp/trail-audit-jj-evidence.json.
