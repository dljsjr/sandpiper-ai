# Cross-project move writes destination parent before validating child rewrites

Confirmed during TCL-174 using a temporary store and the built CLI. Create APP-1 parent and APP-2 subtask. Hand-edit child kind to the valid YAML sequence kind: [TASK]. Rebuild index, then task move APP-1 --project DEST. The command fails with the surgical-writer kind-form error, but APP/APP-1.md and DEST/DEST-1.md both remain, along with the original child. Root: moveTask writes parent before moveSubtasks parses/prepares all child edits; planMove also persists counters. Prepare/validate all expected file rewrites before the first write. Keep this separate from crash-safe multi-file transactions, which are not authorized by the audit. Add a failure-path regression that checks task files, tombstones, history, and counters.
