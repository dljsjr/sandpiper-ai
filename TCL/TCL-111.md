# Subtask creation can create parent directories containing embedded newlines

Inbox report from ~/.sandpiper/agent/inbox/sandpiper-tasks-cli-newline-directory-bug.md:

When creating subtasks, `sandpiper-tasks task create -k SUBTASK --parent <key>` sometimes creates the subtask directory with a newline embedded in the directory name.

Observed in YAAMS project:
- Expected: `.sandpiper/tasks/YAAMS/YAAMS-48/YAAMS-49.md`
- Actual directory: `.sandpiper/tasks/YAAMS/YAAMS-48\nYAAMS-48/YAAMS-49.md`

Hypothesis: CLI output is being captured into the directory path.

Observed with both `YAAMS-42` and `YAAMS-48` subtask creation.

Reproduction attempt:
```bash
sandpiper-tasks task create -p YAAMS -k SUBTASK --parent YAAMS-48 -t "test" --priority HIGH --reporter USER
```

Then check `.sandpiper/tasks/YAAMS/` for directories with embedded newlines.
